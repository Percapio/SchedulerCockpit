| Condition | Cause | Pane shows |
| --- | --- | --- |
| `DocumentMissing` | The `.docx` was deleted from `uploads/` outside the app | The expected path and that the audit must be re-ingested |
| `DocumentUnreadable` | Corrupt zip, `PermissionError`, file open exclusively elsewhere | The underlying reason, verbatim |
| `NoTablesFound` | A `.docx` with no tables | "No build-note tables in this document" |
| No `Notes` source file | The audit was ingested without one | "No build notes attached" — not an error |
| Undecodable medium | EMF/WMF, a corrupt blob, a degenerate decode (§3.4) | Inline placeholder naming the format; the rest of the table renders |
| Merge conflict | Malformed or overlapping `vMerge` (§3.2) | Nothing — the cell renders unmerged; recorded in `anomalies` only |

**The "no `Notes` source file" row never reaches the renderer.**
`render_build_notes` is only called with a path, so the `None` case is decided
one level up: the pane's render trigger checks `notes_docx_path is None` first
and shows the not-attached message directly. Folding it into
`NotesRenderFailure` would make an ordinary state — an audit ingested without
build notes — into a failure value that every caller has to distinguish from a
real one.

The audit still loads in every case. This is a stronger requirement than the
current pane has: today a render failure would surface through
`ChecklistService.load`, which is on the audit-load path.

## 8. Coupling and blast radius

- **`ChecklistService`** loses its notes branch, its `ImageCacheService`
  constructor dependency, and — with `notes_rows` gone from `ActiveAuditView` —
  its only filesystem dependency. It returns to being four repositories and
  sqlite, which is what it was before Phase 42.
- **`ActiveAuditView`** trades `notes_rows: Sequence[NotesRowView]` for
  `notes_docx_path: Path | None`. The lookup already exists at
  [checklist.py:147](../cockpit/services/checklist.py#L147); it stops feeding the
  image cache and starts feeding the view.
- **`AuditSession`** is unchanged. It was reduced to load-only by Patch 07 and
  stays there.
- **`CenterPager`** loses the `settings` parameter Patch 07 added
  ([center_pager.py:89](../cockpit/ui/widgets/center_pager.py#L89)) and keeps the
  relay at [center_pager.py:90](../cockpit/ui/widgets/center_pager.py#L90),
  `notes_pane.empty_space_clicked → self._canvas.empty_clicked.emit`. The
  `empty_clicked` signal belongs to `LayoutCanvas`, which `CenterPager` receives
  by injection and this patch does not touch; only the pane on the emitting side
  changes.
- **`empty_space_clicked` needs a new emitter.** The current pane raises it from
  an event filter on a `QScrollArea` viewport, which no longer exists. A
  `QTextEdit` has no such signal, so `BuildNotesPane` overrides
  `mousePressEvent`: `cursorForPosition(event.pos()).currentTable()` returning
  `None` means the click landed outside every table, and the signal is emitted.
  A click inside a table falls through to `QTextEdit` so selection still works.
  This is the same predicate §4 uses to decide whether to offer the copy action,
  and it should be one helper, not two.
- **`SelectionCoordinator`** loses `register_notes_pane` entirely. The notes pane
  has no rows and no keys, so `set_selected_row`, `clear_selected_row`, and
  `scroll_to_row` — already no-op stubs — are deleted rather than reimplemented.
- **`bootstrap`** drops the `ImageCacheService` construction
  ([bootstrap.py:207](../cockpit/ui/bootstrap.py#L207)) and gains the one-time
  `notes_media/` removal (§6).
- **Ingestion** keeps parsing the `.docx` and keeps rejecting malformed ones. It
  stops writing notes rows.

## 10. Sequencing

1. **The renderer, standalone** (§3). A pure function from a path to a
   `QTextDocument`, with the fixture suite above. No wiring, nothing deleted
   yet — this is where the fidelity questions of §3.2 and §3.5 get answered
   against a real build note before anything is thrown away.
2. **`cell_mime_data` and the context menu** (§4). Also standalone; operates on
   a document produced by step 1.
3. **Pane replacement** (§3.1, §5). `BuildNotesPane` renders lazily, highlights
   instead of filtering; `ActiveAuditView` carries the path; `ChecklistService`
   loses its notes branch; `SelectionCoordinator` loses its notes registration.
   The old grid is deleted here. **First point at which the feature is usable.**
4. **v16 plus the persistence teardown** (§2, §6). Tables, repository, types,
   ingestion writes, `image_cache.py`, reconciler sweep, config fields, theme
   tokens, and the `QSettings` threading revert.

Steps 1 and 2 are additive and land independently. Step 3 is the cutover. Step 4
is pure removal and is deliberately last: if step 3 reveals that the renderer
cannot match the document, the stored rows are still there to fall back on.
Reversing that order trades a revert for a re-ingest.

One problem the audit did not reach, found while defining `RenderPalette`:

- **An accurate render on a dark application is an unreadable one.** A Word
  build note is authored black-on-white and mostly does not set `w:color`; the
  application is dark. Rendering the document's own colours onto the app's
  ground would put black text on `#2A2A2A`. §3.3 gives the pane a document
  ground of its own, so the Build Notes page reads as a white page inside a dark
  application — deliberately, and recorded as A8. This is the kind of defect that
  would have been found only by running it.

## Assumptions

- **A1** — Build notes are always `.docx`, always table-structured, and follow a
  consistent format. This is the premise the patch was requested on. A `.doc`
  (OLE, not OOXML) would fail `UNREADABLE_DOCUMENT` at ingestion today, so the
  renderer never sees one.
- **A2** — Structural fidelity is sufficient and pixel fidelity is not required
  (§3.5). The escalation path is PDF conversion, and it costs the copy feature.
- **A3** — 96 DPI is the right conversion for both EMU and twips. On a
  high-DPI display Qt applies its own device pixel ratio on top, so the render
  stays physically correct; it is logical pixels that are being computed here,
  not device pixels.
- **A4** — The Build Notes pane ignores the global font scale (§3.3). This makes
  it the one view in the application where the Settings font size has no effect,
  which is the correct trade for a document render but will read as a bug to
  anyone who does not know why.
- **A5** — Lazy rendering on first page-switch is acceptable, and the departure
  from Phase 41 A9's rebuild-on-reload is justified by cost: rows were cheap,
  documents are not.
- **A6** — HTML with `data:` URIs is accepted by the applications these cells get
  pasted into. Word and Outlook are the stated targets. If a target refuses data
  URIs, adding `image/png` to `cell_mime_data` is additive (§4.2).
- **A7** — Deleting `build_notes_checklist` loses nothing unrecoverable, because
  the `.docx` is retained by `reference_count > 0` and the orphan sweep. Verified
  rather than assumed: `SourceFileRepository.reference_count` is
  `SELECT COUNT(DISTINCT audit_id) FROM source_files WHERE file_hash = ?`
  ([source_files.py:56-62](../cockpit/persistence/repositories/source_files.py#L56-L62)).
  It reads `source_files` and nothing else, and a search across `cockpit/` finds
  only two references to `build_notes_checklist` outside `schema.py` and its own
  repository — both in the split-clone, neither on a retention path. Dropping the
  table cannot change any file's reference count.

  If a `.docx` is ever lost, the notes are lost with it — under the old design
  the parsed rows would have survived. That exposure is accepted and is the same
  one Phase 42 §3.4 accepted when it made a missing `.docx` a hard migration
  failure, though it widens from migration-time to always.
- **A8** — The Build Notes page reads as a white document on a dark application
  (§3.3). That is the intended appearance. If it is judged wrong in use, the
  alternative is remapping the document's colours to the theme, which reintroduces
  exactly the fidelity loss this patch removes.
- **A9** — Decoding at display size (§3.4) is sufficient to keep the render
  synchronous. It rests on build notes being pages a human laid out, so the total
  displayed pixel area is small. `max_document_media_px` is the guard for when
  that is untrue; its value is chosen, not measured.
